# Security policy

## Supported versions

LumaKnob is currently an alpha. Security fixes are applied to the latest
prerelease and the `main` branch; older test builds are not supported.

## Report a vulnerability privately

Please use GitHub's
[private vulnerability reporting](https://github.com/Humancannonball/LumaKnob/security/advisories/new).
Do not open a public issue for a vulnerability that could strand users behind
an opaque shade, execute untrusted input, expose local data, or compromise the
release process.

Include the affected version, reproduction steps, impact, and any proposed
mitigation. Remove usernames, EDID serial numbers, and unrelated machine data
from logs. You should receive an acknowledgement within seven days; timelines
for a fix and coordinated disclosure depend on severity and reproducibility.

Ordinary monitor compatibility failures are not security vulnerabilities, but
recovery failures are treated with security-level urgency. Use the public
device-report form only when the report can be disclosed safely.

LumaKnob will never ask users to disable SmartScreen, antivirus, UAC, or other
Windows security controls.
